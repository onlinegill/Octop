# Team Memory

This records the team's long-lived shared understanding, not a running log of individual tasks.

The host reads and writes it with the memory tools; when dispatching, excerpt the shared understanding a member needs into the task message. Members will not read this file automatically.

## What to write

- Preferences, boundaries, and delivery formats the user repeatedly emphasizes
- The role split already agreed on (who is good at what, who should not take what)
- Terminology, conventions, and naming that hold across tasks

## What not to write

- The full text of a single dispatch (that is a conversation, not memory)
- Stale temporary decisions
- Drafts and file-path details that belong to a single member's workspace

## How to use it

Before starting a new task, skim it: is there something already agreed that you do not need to ask the user about? If so, put it in the dispatch; if not, ask one question.
